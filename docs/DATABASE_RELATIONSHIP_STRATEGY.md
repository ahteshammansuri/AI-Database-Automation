# Database Relationship & Foreign-Key Strategy

**Target Database:** MySQL (InnoDB Relational Engine)  
**Execution Safety:** Zero Arbitrary AI IDs — Deterministic Resolution Only  

---

## 1. Problem Statement

LLMs are prone to hallucinating foreign key integer identifiers. For instance, generating an article about "Kubernetes" might prompt an LLM to invent `category_id: 42`. If `category_id: 42` does not exist in the customer's `categories` table, the foreign key constraint `fk_posts_category` rejects the insertion with a MySQL integrity constraint violation.

The platform never asks an LLM for an integer ID. Instead, it asks the LLM for a semantic business label (e.g., "DevOps & Cloud") and resolves the actual primary key deterministically using real MySQL queries and policy rules.

---

## 2. Six Foreign-Key Resolution Modes

For every foreign key discovered in the target schema (e.g., `posts.category_id` -> `categories.id`), operators can select one of six deterministic modes:

1. **SELECT_EXISTING:**
   - Operator selects an existing record from a searchable dropdown displaying human-readable labels (e.g. "DevOps & Cloud").
   - The verified primary key (`1`) is bound behind the scenes.
2. **FIXED_DEFAULT:**
   - A static pre-selected record ID is used for all executions.
3. **INFER_WITH_AI:**
   - AI proposes a business label based on content topic.
   - Deterministic query searches the related table by `name` or `slug`.
   - If exactly one match exists, that ID is bound. If multiple matches or no match exist, execution pauses or falls back to default.
4. **CREATE_IF_MISSING (Recommended for Categories/Tags):**
   - AI proposes a business label.
   - Deterministic query checks for an existing record in the related table.
   - If not found and the related table is allowlisted for writes:
     1. Inserts the parent record into the related table inside the active transaction.
     2. Retrieves the actual generated auto-increment primary key via `PDO::lastInsertId()`.
     3. Binds this real primary key to the child record.
5. **GENERATE_RELATED_WITH_AI:**
   - Full parent record is generated by AI, validated, and inserted first in the transaction before child row insertion.
6. **REQUIRE_USER_REVIEW:**
   - If relation resolution is ambiguous, execution pauses in `PENDING_APPROVAL` requiring operator selection in the portal.

---

## 3. Concurrency & Unique Race Handling

When multiple background workers process executions concurrently:
- A simple "check then insert" query is vulnerable to race conditions if two workers attempt to create the same category concurrently.
- `SafeDatabaseExecutor` handles unique key collisions by catching `PDOException (SQLSTATE 23000 / Error 1062)` on duplicate unique slugs/names and immediately re-querying the existing row to obtain its valid ID.
- The entire operation executes inside `PDO::beginTransaction()` and rolls back cleanly if any constraint fails.
